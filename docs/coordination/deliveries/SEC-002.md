1. **Lectura y Escritura en `data/gwen_db.json` (Demostrado en Código):**
   - La inspección de `src/server/db.ts` demostró que las constantes `DATA_DIR` y `DATA_FILE` se calculan en el momento de importación utilizando `path.join(process.cwd(), "data")` y `path.join(DATA_DIR, "gwen_db.json")`.

   - En `src/server/db.ts`, la variable `connectionString` evalúa `process.env.DATABASE_URL || process.env.POSTGRES_URL` e instancia inmediatamente un `Pool` de PostgreSQL al evaluarse el módulo si alguna de esas variables existe.
   - Sin un aislamiento previo al import, existía el riesgo potencial de establecer conexiones involuntarias contra bases de datos PostgreSQL si tales variables estaban definidas en el entorno o en el archivo `.env`.

## 2. Correcciones Implementadas en `scripts/test_auth_suite.ts`

1. **Setup de Aislamiento Protegido dentro del Bloque `try ... finally`:**
   - Se capturan las referencias originales (`originalCwd`, `serverTsPath`, `repoRoot`, snapshot de `process.env`) antes de cualquier mutación.
   - La alteración de variables de entorno, la creación del directorio temporal con `fs.mkdtempSync` y el cambio de `process.chdir(tempDir)` se ejecutan dentro del bloque `try`, garantizando que si el setup llegara a fallar, el bloque `finally` se ejecuta siempre para restaurar el entorno y el directorio de trabajo.

2. **Aislamiento Previo al `import` Dinámico de `db.js`:**
   - Se eliminaron `import` estáticos de base de datos y `dotenv.config()` a nivel raíz.
   - Se neutralizan explícitamente `DATABASE_URL` y `POSTGRES_URL` (`delete process.env[...]`).
   - Se configuran las variables `TEST_MEMORY_ONLY = 'true'` y `NODE_ENV = 'test'`.
   - Se eliminan todas las variables `SUPERADMIN_BOOTSTRAP_*` heredadas del entorno.
   - Se crea un directorio temporal exclusivo mediante `fs.mkdtempSync(path.join(os.tmpdir(), 'gwen-auth-suite-'))`.
   - Se cambia el directorio de trabajo actual a `tempDir` (`process.chdir(tempDir)`) **antes** de realizar el `await import('../src/server/db.js')`, asegurando que `db.ts` dirija cualquier fallback y búsqueda de dotenv a dicho temporal aislado.

3. **Lectura Estática Inmune a Cambios de `cwd`:**
   - La ruta `serverTsPath` se resuelve de forma absoluta contra `repoRoot` antes de cambiar de directorio, garantizando que las comprobaciones de ausencia de credenciales y endpoints en `server.ts` se lean correctamente sin importar el `cwd` activo.

4. **Validación Estricta de Directorio Temporal en `rmSync`:**
   - En el bloque `finally`, antes de eliminar el directorio temporal, se valida rigurosamente que:
     - `path.dirname(path.resolve(tempDir)) === path.resolve(os.tmpdir())`
     - `path.basename(path.resolve(tempDir)).startsWith('gwen-auth-suite-')`
   - Esto previene cualquier comprobación laxa de prefijos sobre directorios padre que pudiera permitir coincidencias erróneas en directorios hermanos.

5. **Restauración y Manejo de Errores sin Ocultar Fallos:**
   - En el bloque `finally`, se restaura `process.chdir(originalCwd)`, se reestablecen las variables de entorno originales y se limpian las variables de bootstrap creadas durante los tests.
   - Si ocurre cualquier fallo durante la restauración o limpieza (o si falla la validación de seguridad de `tempDir`), el error se registra y se marca `cleanupFailed = true`, asignando `process.exitCode = 1` para no enmascarar el fallo de cleanup como un resultado exitoso.
   - No se utiliza `process.exit()` antes de la finalización completa del bloque `finally`.
