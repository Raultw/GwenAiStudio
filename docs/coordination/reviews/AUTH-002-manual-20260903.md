## Correcciones requeridas antes de aprobar

1. **Alta — Cambio inicial eludible** (`server.ts:1290–1322`, `src/server/db.ts:3558`). Al suministrar password, el POST conserva `mustChangePassword=false` por defecto o acepta el valor enviado. El formulario de empleados suministra password si se escribe. Exigir desde backend cambio inicial para toda cuenta provisionada administrativamente, sin depender del body; separar explícitamente cualquier bootstrap existente que necesite otro contrato. Cubrir clave explícita, omitida y petición maliciosa con flag false.
2. **Alta — Éxito falso al provisionar/restablecer** (`ProfessionalManagementAdmin.tsx:251–303`). Los fetch de creación, edición de usuario y reset no verifican `response.ok`. Un 400 por clave inválida o configuración ausente termina cerrando modal y mostrando profesional creado/actualizado. Comprobar cada respuesta y mostrar fallo o éxito parcial real (el profesional ya puede haberse guardado); reintento sin duplicar usuario/profesional. No informar reset exitoso si falla. Probar 400/401/403/500 y red con el componente real.
3. **Media — UX de provisión incompleta** (`ProfessionalManagementAdmin.tsx:852–860`). Sigue mostrando “Contraseña de Acceso *” y “Mínimo 6 caracteres”; no explica clave temporal configurada ni presenta al administrador el username generado. Alinear con flujo acordado, no transformar contraseñas con trim y mostrar usuario resultante sin revelar secretos en logs. No exigir email.
4. **Media — Evidencia/documentación inexacta.** La entrega afirma que updateUser dejó de modificar contraseñas, pero mantiene hashing, escritura de password_hash y must_change_password (`db.ts:3634–3674`). El endpoint HTTP sí filtra estos campos. Decidir contrato interno explícito, eliminar el bypass en persistencia según alcance y adaptar pruebas; no conservar tests que exijan el comportamiento que se dice eliminado. La nueva suite prueba una copia local de filterUserUpdates, no el handler real; sustituirla por ejecución de código real extraído o integración aislada. Sus cinco casos login son memoria secuencial, no cinco pruebas de concurrencia. Corregir ROADMAP y entrega.
